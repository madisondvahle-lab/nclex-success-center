## Step 2 — what exists now
- **Coach workflow:** `madison-study-plans.html` → **Assign a week**. Choose a Monday and one student or all active NCLEX students with saved plans. Save plan edits before generating. The dated list shows each assignment and completion state. Search/plan editing remains unchanged.
- **Data:** `supabase-weekly-assignments-migration.sql` adds `assignment_week`, `assignment_kind` (`practice` / `cat`), and `assignment_details` to the existing `student_resources`. No competing assignment table. Snapshot details include platform, count, categories, topics, mode, and (for portal practice) question IDs. Unique student/date/kind index and per-student row locks prevent duplicate generation, including concurrent reruns. Existing assignments and completion are never overwritten when focus changes.
- **Admin-only RPC:** `generate_weekly_assignments(p_week, p_student)` returns created/existing counts plus per-student/date failures. With no student argument, it uses all active non-nursing students with saved plans. Plans need at least 3 distinct practice days without a CAT (the user-directed rule in #174); otherwise generation skips that student and reports the problem. Days are fully per-student, including weekends; the UI uses `WeeklyPlan.practiceOnlyDays` / `meetsPracticeMinimum`. Missing focus blocks targeted practice, not CATs. Archived/nursing students are excluded. Generation does not run automatically on save or deployment.
- **Portal practice:** stored links use `supplemental-practice.html?assignment=<resource UUID>`. Frozen IDs must all still be active MCQs when launched; insufficient or retired questions fail explicitly without silently substituting unrelated items. Generation canonicalizes existing category/subcategory labels using the rules in `category-names.js` (underscores normalized). It does not infer categories from question stems, modify questions, or activate drafts. Selected categories are ORed; selected topic labels are ORed; when both are present they must both match. Topics match bank labels exactly, ignoring case/outer whitespace. Only supported MCQs are selected; no new NGN rendering or clinical content.
- **Mode:** portal assignments use the existing ExamUI without immediate correctness feedback; rationales appear after submission. External practice instructions specify timed practice, tutor mode off, followed by rationale review. External platform categories/topics must be selected manually; there is no UWorld/Archer integration or automatic result import.
- **CATs:** one full CAT/readiness assignment on each saved CAT day; external CATs are manual, portal CATs reuse `diagnostic.html?mode=mock`. They are not restricted to focus categories. Students log CAT reports using the existing dashboard card and mark the dated assignment complete.
- **Per-CAT settings and NCLEX cutoff:** `cat_assignments` in a student's saved plan can override platform, task title, and instructions for each CAT weekday. The admin editor exposes a per-day configuration; student recurring plans and generated assignments show the saved task, and reminders use its generated title/note. CAT generation snapshots these settings and never rewrites existing dated assignments. Platform options include Remar and NurseMeg. The same `supabase-weekly-cat-details-migration.sql` also updates the existing admin-only generation RPC to skip assignment slots on/after a student's NCLEX target date without changing its access controls. ## Step 3 — dashboard reminders
- `student-dashboard.html` shows **Assignment reminders** immediately after the welcome area for both NCLEX and nursing students, independent of nursing class selection. It reuses the existing student-scoped `student_resources` query; no template is interpreted as generated work.
- `WeeklyAssignments.reminders` selects incomplete generated practice/CAT records only: all overdue work, practice/CAT due today or tomorrow, plus the earliest future CAT date. Completed records (including completed prior weeks) are excluded; the next CAT advances when an earlier CAT is completed. Dates use the student's local calendar, not UTC date truncation, and invalid dates produce a visible warning instead of silently rolling into another month.
- Each reminder shows urgency, calendar date, saved title/platform/count, stored portal action link, and expandable assignment instructions. External-platform records intentionally have no URL: they show manual-setup instructions, not an invented integration or a broken-link error. Unsafe URL protocols are not rendered.
- Reminder completion reuses `set_weekly_assignment_complete` and the existing Assigned work completion handler. Successful completion removes the reminder and updates NCLEX Assigned work/weekly totals; failed saves remain visible without changing completion. Returning from another tab (focus/visibility), restored browser history, and **Refresh** reload actual records, including portal auto-completion. No assignments are generated by reminder loading.
- Empty assignment, all-complete, future-only, missing/invalid date/link, failed-load/retry, and failed-completion states are explicit. On a resource-load failure, reminders are withheld rather than presenting stale assignments as current; NCLEX Assigned work and weekly progress also show unavailable.

## Step 4 — weekly review / retarget queue
- **Where:** `madison-study-plans.html` → **Weekly review** (first section). Pick a week (snaps to its Monday; Prev/Next), filter (To review / All / Next week assigned / No plan), search, Refresh. Pure logic lives in `weekly-review.js` (`WeeklyReview.range/results/rows`).
- **Per student row:** status, completed/total generated assignments for the week (practice and CAT split, overdue count), recorded results dated in that week, and factual flags (no plan, nothing generated, overdue, no focus, "N CATs marked complete; M CAT/readiness scores recorded"). Rows sort To review → No plan → Next week assigned, then oldest `focus_updated_at`, then name. Nursing students are also listed (status **Nursing**, sorted last, filter "Nursing students (review only)") with any generated assignments, overdue count, and recorded results, but plan editing and next-week generation are disabled with a visible reason because plans and `generate_weekly_assignments` are NCLEX-only by design; a stray plan row never makes a nursing student assignable.
- **Results sources (admin RLS reads, unchanged):** `external_assessments`, `student_assessment_uploads` + `student_assessment_categories`, `student_supplemental_practice_results`, `in_house_assessment_attempts`; platforms normalized with `assessment-platforms.js`, categories with `category-names.js`. Missing test date falls back to the logged date and is labeled so. **Details** lists each result with category scores lowest-first, "current focus" and "low sample" (<5 questions) markers. Completion is labeled self-reported; scores are labeled recorded. Results are never linked to specific assignments, and nothing is suggested automatically — the tutor decides focus.
- **Actions:** **Edit focus & plan** opens the existing editor; saving states that new focus applies to assignments generated afterwards and existing snapshots keep their original focus. **Assign next week** calls the existing idempotent `generate_weekly_assignments` for that student (button reads "Fill missing next-week days" when some exist; busy-locked per student; blocked while that student's editor has unsaved changes or the plan has <3 non-CAT practice days). Existing/completed assignments are never overwritten.
- **Reviewed state:** derived, not stored — a student leaves "To review" once next week has generated assignments. No migration, no new table.
- **Errors:** assignment-load failure shows no rows ("nothing is shown so completion isn't misreported"); a failed results source marks results Unavailable with a warning and suppresses CAT-score flags.
- **Validation:** `node --test tests/weekly-review.test.cjs` (week ranges across DST/time zones, result normalization/filtering, row counts/flags/order, nursing review-only rows, page wiring + inline script compile). Live read-only check confirmed all queried columns exist and admin SELECT policies cover each source. Fixture-only Playwright Chromium at 1366×900 and 390×844: auth redirect, summary/order/filters, details, dirty-editor block, save message, assign once + idempotent rerun, week navigation, partial/total failures, no overflow/page errors. No real student data written.
- **Limits:** nursing students are review-only (no plan/generation); no persistent "reviewed" marker; completion is self-reported; external platform results appear only if logged/uploaded; no automatic retargeting, emails, or integrations.
